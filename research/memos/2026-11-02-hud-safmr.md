# HUD Small Area Fair Market Rents (SAFMR)

**Recommendation: recommend**

## What it is
SAFMR is HUD's annual, ZIP-code-level rent benchmark (by bedroom count: 0–4+ BR) used to set Section
8 payment standards. It's calculated from ACS/American Housing Survey rent data at roughly the
40th–50th percentile of the local rental market. Standard (county/metro-wide, non-ZIP) FMRs cover
the rest of the country where SAFMR isn't designated.

Source: https://www.huduser.gov/portal/datasets/fmr.html — one XLSX/CSV file per federal fiscal year,
covering all ZIPs and bedroom sizes nationwide. Also mirrored on HUD's ArcGIS Open Data hub and
catalog.data.gov as CSV/GeoJSON/Shapefile.

## Why it could help
This project's rent inputs are currently:
- **Zillow ZORI** (`zillow_research.py`) — ZIP-weighted to NTA, free, but a single blended-tier rent
  index, not broken out by bedroom count.
- **RentCast** (`rentcast.py`) — capped at 31 requests/month with a 24h cooldown, and only covers the
  5 hand-picked NYC search areas in `sources.yaml`.

Neither gives a free, by-bedroom-count, nationally-available rent reference. `investment.py`'s
`BEDROOM_RENT_FACTOR` already assumes rent scales with bedroom count relative to "the neighborhood's
typical (ZORI) rent" — SAFMR would let that factor be checked against (or replaced by) an actual
by-bedroom number instead of a fixed multiplier, and would extend rent coverage to any US ZIP the
project generalizes to, independent of RentCast's budget or search-area list.

## Evaluation
- **Coverage/granularity**: national; HUD's own ArcGIS dataset description says SAFMRs are
  "calculated for ZIP Codes within Metropolitan Areas" (including NYC), with county/metro-wide FMR
  elsewhere. Exact count of SAFMR-designated metros not verified first-hand this run.
- **Update frequency**: annual (FY starts Oct 1, file usually published ~August).
- **History**: **not verified this run** — search results gave no start year for SAFMR specifically
  (as opposed to standard FMRs, which go back decades). SAFMR is a newer, separate program, so its
  own history is likely shorter; confirm the actual start year on huduser.gov before relying on it
  for a multi-year backtest.
- **Cost**: free, no rate limit observed on the bulk files.
- **License**: produced directly by HUD (federal agency), so public domain / no copyright is the
  expected default — but **not independently confirmed**: huduser.gov was unreachable from this
  session (blocked by network policy, see below), so this is inferred from the agency/program, not
  read off HUD's own ToS/disclaimer page. (A *third-party* API at fairmarketrentmap.com wraps the
  same data behind a paid key — don't use that one.)
- **Correlation**: not computed — `app/research/evaluate_series.py` (Phase 4) doesn't exist yet.
  Qualitatively it should track ZORI closely by construction (both are rent-level estimates), with
  SAFMR lagging roughly a year.

## Recommendation
Implement as a new `neighborhood`-kind source, ZIP → NTA weighted the same way `zillow_research.py`
already does for ZORI. Expected-clean federal licensing and true national coverage make it a good
complement to ZORI/RentCast — a free, unlimited fallback that reaches areas RentCast's budget/area-list
never will. **Before implementing**, confirm directly on huduser.gov that there's no ToS/login wall on
the bulk files and check the actual SAFMR start year — both were unverified this run because
huduser.gov could not be reached from this session. Annual cadence means it supplements rather than
replaces listings-derived rent estimates where those exist.
