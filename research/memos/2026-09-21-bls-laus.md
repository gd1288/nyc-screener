# BLS Local Area Unemployment Statistics (LAUS)

**Candidate file:** `research/candidates/bls-laus.json`
**Verdict: do_not_recommend**

## What it is
BLS's monthly county/city/metro unemployment and labor-force series, back decades for most
counties. Free "Public Data API": v1 works with no registration (25 queries/day, 10-year window
per query), v2 registration (still free) raises the cap to 500 queries/day and a 20-year window.
https://www.bls.gov/lau/

## Why it was considered
`census_acs.py` is currently the project's only demographic/economic signal, and it's ACS 5-year
estimates refreshed twice a year — slow-moving by design. Monthly county unemployment looked like
a plausible faster-moving complement for the "demographic shift" pillar in `neighborhood.py`.

## Evaluation
- **Coverage/granularity:** national, county/city level. Fine in principle.
- **Cost/license:** free, public-domain federal data, no login required for basic access. Clean.
- **History:** decades available for most counties. Fine.
- **Correlation:** not computed (`evaluate_series.py` doesn't exist yet).
- **Practical issues surfaced during evaluation:**
  1. BLS itself documents that **county-level LAUS is not seasonally adjusted** — a raw
     month-over-month read is noisy and would need a trailing-12-month or year-over-year
     transform before it's usable, which is more preprocessing than any other candidate here needs.
  2. NYC is only 5 counties (one per borough), so this project's actual per-neighborhood use case
     gets essentially no cross-sectional signal from county-level unemployment — all NYC
     neighborhoods would share the same county-level value regardless of how different their
     conditions are, which is far coarser than what `census_acs.py` already provides at
     tract-aggregated-to-NTA granularity.
  3. The API requires per-geography BLS series-ID lookups rather than a bulk file pull, adding
     more adapter complexity than the CSV-based candidates in this batch.

## Recommendation
Do not implement now. It's a legitimately free, licensed-clean national source, but for this
project's current NYC/NTA-level use case it adds noise-prone, coarse-grained data that duplicates
what `census_acs.py` already covers better, for more adapter complexity than the other candidates.
It would be worth revisiting once the project has neighborhoods spread across counties with real
labor-market variation (i.e., once it's genuinely multi-metro), where county-level unemployment
would actually carry cross-sectional signal.
