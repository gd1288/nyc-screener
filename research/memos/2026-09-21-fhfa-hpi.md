# FHFA House Price Index (HPI)

**Candidate file:** `research/candidates/fhfa-hpi.json`
**Verdict: recommend**

## What it is
The Federal Housing Finance Agency's House Price Index — a repeat-sales index of single-family
home prices, published quarterly at national, census-division, state, MSA, county, ZIP, and
census-tract levels, with the all-transactions index running back to 1975. It's the standard
academic/industry benchmark for regional home-price appreciation, built from Fannie Mae/Freddie
Mac mortgage data plus (for the expanded-data index) FHA and county-recorder transactions. Plain
CSV/XLSX bulk downloads at https://www.fhfa.gov/data/hpi/datasets, no login, no API key.

## Why it could help
The project's only price-history series today is Zillow ZHVI (`zillow_research.py`), pulled by
ZIP code from Zillow's public research CSVs. That's fine for NYC but ZIP-level ZHVI coverage and
history thin out fast outside Zillow's core metros — exactly the gap that matters if this project
is going to generalize past NYC condos, per its own stated goal. FHFA HPI is available down to
county and tract for literally every US county, with 50 years of history for the all-transactions
series.

There's also a more concrete, immediate hook: this project's own `research-sources` skill
describes the (not-yet-built) `app/research/evaluate_series.py` quantitative-evaluation step as
checking new candidates' correlation against "FHFA tract HPI growth and Zillow ZORI." Right now
that benchmark doesn't actually exist as a data source in this repo — it's referenced but never
ingested. Adding FHFA HPI as a real source is a prerequisite for that Phase 4 evaluation tool to
work as designed, independent of whatever else it'd be used for in scoring.

## Evaluation
- **Coverage/granularity:** national down to tract; well past what's needed for NYC NTAs and
  ready for county/MSA-level use once the project covers other cities.
- **Cost/license:** confirmed free, no login, plain government bulk files. Public domain (federal
  statistical product). No caveats here, unlike the mortgage-rate candidate below.
- **History:** all-transactions index back to 1975, purchase-only back to 1991 — long enough for
  the kind of 10-year backtest `scoring/backtest.py` already does with Zillow's shorter history.
- **Quantitative correlation:** not computed — `app/research/evaluate_series.py` doesn't exist yet
  in this repo (Phase 4 of the roadmap isn't built), so this step of the procedure was skipped by
  necessity, not by choice. Worth noting explicitly rather than silently omitting.

## Caveat: condo coverage not yet confirmed
I ran out of search budget before checking one important detail: FHFA HPI is built primarily from
conforming-mortgage repeat-sales transactions, which historically skew single-family. Whether the
purchase-only/all-transactions index actually includes enough condo sales to be a like-for-like
comparator for this project's condo-specific scoring — versus being more useful purely as a
regional appreciation-trend/backtest benchmark — needs to be confirmed as the first step of
implementation, before it's wired into any condo-specific metric.

## Recommendation
Approve. This is the cleanest candidate of the batch: unambiguous license, genuinely national and
tract-level, decades of history, and it fills a real gap both in scoring inputs and in the
project's own planned backtest tooling. Implementation would look like `zillow_research.py` —
download and parse a bulk CSV/XLSX, map to NTA/tract, write to `neighborhood_metrics` — no API key
or scraping involved. First implementation step should be confirming condo coverage (see caveat
above) so it's used correctly (regional benchmark vs. direct condo comparator).
